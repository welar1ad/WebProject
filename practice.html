Практика: один проект тремя инструментами

Возьмём небольшой статический проект и соберём его по очереди Vite, Webpack и Gulp. Исходники одни и те же, меняется только инструмент сборки, поэтому разницу в настройке видно напрямую.

Исходный проект

  • index.html — разметка страницы;
  • src/js/app.js — модуль JavaScript, который импортирует другой модуль;
  • src/scss/main.scss — стили на SCSS;
  • src/images/ — несколько изображений.

Задача одна: на выходе получить каталог с готовой страницей, собранными стилями и оптимизированными изображениями.

Сборка на Vite

  1. Установить пакет: npm install --save-dev vite.
  2. Добавить в package.json команды dev и build.
  3. Указать входной HTML-файл в vite.config.js, если структура нестандартная.
  4. Запустить разработку командой npm run dev, сборку — командой npm run build.

Vite сам компилирует SCSS, если установлен пакет sass, и копирует статику из каталога public.

Сборка на Webpack

  1. Установить webpack, webpack-cli и загрузчики для SCSS.
  2. Задать точку входа в поле entry и каталог результата в output.
  3. Описать правила для .scss с загрузчиками sass-loader и css-loader.
  4. Подключить HtmlWebpackPlugin, чтобы HTML создавался автоматически.
  5. Собрать проект командой npx webpack --mode production.

Сборка на Gulp

  1. Установить gulp и плагины gulp-sass, gulp-imagemin.
  2. Описать задачу styles для компиляции SCSS.
  3. Описать задачу images для сжатия изображений.
  4. Объединить задачи в одну через series и запустить её командой npx gulp build.

Во всех трёх случаях получается рабочая страница. Vite потребовал меньше всего настроек, Webpack — отдельной конфигурации для загрузчиков, а Gulp — задачи под каждый тип файлов. Если проект состоит из модулей, сборщик избавляет от ручной настройки загрузчиков; если нужно только обработать файлы, достаточно таск-раннера.
